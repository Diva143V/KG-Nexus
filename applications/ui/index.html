Conflict Resolution Strategies Explained

When Graph A and Graph B provide contradictory facts for the same canonical entity or predicate, the Hybrid Fusion Engine applies your selected policy.

Example Scenario: Conflicting Assertions

Two distinct datasets claim contradictory relationships for the same canonical entity:

Graph A: Entity_A → relates_to → Target_1
⚠️ CONFLICT
Graph B: Entity_A → opposes → Target_1
Policy System Behavior Trade-off Recommended Use Case
PRESERVE Both assertions retained with distinct PROV-O provenance trails Larger graph size, resolves conflicts downstream Scientific research, literature mining, clinical audit trails
REJECT Conflicting duplicate assertions are removed from the release Clean graph, risk of discarding real domain variance Strict production ingestion of known authoritative schemas
REVIEW Assertions kept but quarantined for human expert verification Requires human review loop, zero automated loss Regulated drug repurposing and high-stakes ontology curation

How to Choose Your Policy:

1. Do you trust one source more than the other?

Yes → Use REJECT

Strict canonical release: keeps assertions from the authoritative source and discards contradictory ones.

No → Proceed to Question 2

2. Do you have capacity to review disagreements manually?

Yes → Use REVIEW

Quarantine mode: flags conflicts for domain curation before merging into release.

No → Use PRESERVE

Non-destructive mode: retains all claims with separate PROV-O provenance trails for downstream audit.
